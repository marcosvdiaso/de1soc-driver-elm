Introdução

Driver feito para comunicação com o CoProcessador ELM embarcado em uma FPGA Terasic DE1-SoC. Toda a implementação foi feita em ARM Assembly.

O driver mapeia a região de E/S mapeada em memória (/dev/mem) da FPGA via mmap, expondo uma API em C que abstrai o protocolo de handshake e o envio de instruções para o coprocessador. O driver então faz todas as chamadas como iniciar inferência, carregar arquivos ou pegar resultado diretamente em conexão com a placa.

Arquitetura de Hardware

Mapa de Registradores

Base física: 0xFF200000 mapeada com mmap via /dev/mem, span de 0x1000 bytes.

Registrador Offset Direção Descrição
DATA_IN 0x00 CPU -> FPGA Palavra de instrução montada (opcode + endereço + valor)
SIGNALS 0x10 CPU -> FPGA Controle de handshake: bit 0 = enable, bit 1 = clear, bit 2 = reset
DATA_OUT 0x20 FPGA -> CPU Status da inferência e resultado (dígito predito nos bits [3:0])

DATA_OUT

Bit Nome Significado
4 DONE Inferência concluída com sucesso
5 BUSY Coprocessador processando instrução
6 ERROR Erro durante a execução
[3:0] RESULT Dígito predito (0–9) após DONE=1

Temporização de Pulso

A FPGA trabalha com 50 MHz (equivalente a 20ns). O processador opera a 800 MHz (ciclo de 1,25ns). A razão entre o ambos é de 16 ciclos ARM por ciclo FPGA. Por conta disso o driver utiliza o dobro, PULSE_WAIT = 32 como iterações de loop, uma margem de segurança para garantir que o pulso seja reconhecido.

Instalação

Dependências

É necessário o toolchain de cross-compilação para ARM Linux:

sudo apt install gcc-arm-linux-gnueabihf

Build

Clone o repositório e compile com make:

git clone https://github.com/marcosvdiaso/de1soc-driver-elm.git
cd "de1soc-driver-elm/Marco 2 - Driver"
make

O Makefile chama:

arm-linux-gnueabihf-gcc -g -std=c99 -marm -o driver main.c driver.s -lm -lrt

Para limpar o binário gerado:

make clean

Arquivos binários necessários

Os pesos e a imagem são embutidos em tempo de compilação via .incbin. É IMPRESCINDÍVEL a existência desses arquivos antes do build:

Arquivo Conteúdo Itens
archives/W_in.bin Matriz de pesos de entrada 100.352 valores Q4.12
archives/b.bin Bias da camada oculta 128 valores Q4.12
archives/beta.bin Pesos de saída 1.280 valores Q4.12
archives/images/image.bin Imagem de entrada 784 bytes

Uso

Certifique-se de que o CoProcessador ELM está gravado e rodando na FPGA. Execute na DE1-SoC (requer permissão de acesso a /dev/mem): 

sudo ./driver

O programa solicita então o dígito esperado e o número de inferências a realizar, imprimindo ao final as métricas de robustez, latência, throughput e jitter.

API Pública

Declarada em driver.h. Todas as funções são implementadas em driver.s.

int elm_open(void)

Abre /dev/mem com open(O_RDWR) e mapeia a região de e/s da FPGA com mmap. O ponteiro do mmap é mantido no registrador r9, preservado ao longo de toda a sessão.

Retorna: 0 em caso de sucesso

Retorna: -1 se falhar ao abrir /dev/mem ou ao mapear

void elm_close(void)

Desfaz o mapeamento com munmap e fecha o file descriptor do /dev/mem. Deve ser chamado ao final da sessão.

void elm_reset(void)

Gera um pulso de reset no coprocessador subindo o bit 2 de SIGNALS por 32 ciclos e depois abaixando.

int elm_load(void)

Sequencia o envio completo de todos os parâmetros do modelo ELM na seguinte ordem: imagem -> bias -> betas -> pesos. Os dados são lidos diretamente das seções .rodata embutidas no binário.

Retorna: 0 se todos os dados foram enviados com sucesso

Retorna: -1 se qualquer etapa reportar erro

Chama internamente: elm_store_img, elm_store_bias, elm_store_beta, elm_store_weights.

int elm_start(void)

Pulsa o sinal de clear (bit 1 de SIGNALS) e envia a instrução OP_START para iniciar a inferência. Aguarda até que DONE ou ERROR sejam setados em DATA_OUT.

Retorna: valor de DATA_OUT com DONE=1 em caso de sucesso

Retorna: -1 se ERROR=1 for detectado

int elm_result(void)

Lê DATA_OUT e extrai o dígito predito nos bits [3:0]. Deve ser chamado após elm_start retornar com sucesso.

Retorna: dígito predito (0–9)

Retorna: -1 se ERROR=1

Opcodes de Instrução

As instruções são montadas pela função interna build_instruction, que combina opcode, endereço e valor em 32 bits enviados para DATA_IN.

Opcode Nome
0b000STORE_IMG
0b001STORE_WEIGHTS_ADDR
0b010STORE_WEIGHTS_VAL
0b011STORE_BIAS
0b100STORE_BETA
0b101START
0b110STATUS
0b111NOP

Os pesos são enviados em duas instruções consecutivas por endereço: primeiro STORE_WEIGHTS_ADDR (índice), depois STORE_WEIGHTS_VAL (valor Q4.12). O handshake garante que a sequência funcione.

Convenção de Registradores (AAPCS)

Registrador Papel no driver
r0–r3 Argumentos e valor de retorno
r4–r7 Usados para preservar estado entre chamadas
r9 Mantém o ponteiro do mmap durante toda a sessão
r7 Número da syscall

Fluxo de Inferência

O fluxo correto de uso da API, conforme implementado em main.c:

elm_open() -> elm_reset() -> elm_load() -> elm_start() -> elm_result() -> elm_close()

Exemplo completo em C

#include "driver.h"
#include <stdio.h>

int main(void) {
    /* Mapeia /dev/mem e faz mmap da FPGA */
    if (elm_open() < 0) { perror("elm_open"); return -1; }

    /* Garante estado inicial limpo */
    elm_reset();

    /* Envia imagem + pesos + bias + beta */
    if (elm_load() < 0){
      printf("Erro ao carregar arquivos.\n");
      return -1;
    }

}
